# Contributing

Thanks for taking a look.

## Ground Rules

- Keep changes focused and easy to review.
- Do not include secrets, local machine paths, tokens, logs, or private runtime state.
- Prefer small pull requests with clear test notes.
- Keep generated artifacts out of commits unless they are required source assets.

## Checks

Before opening a pull request, run the relevant test, build, or lint command for the files you changed and include the command output in the PR notes.
